# Mapeamento Ruby → extensão Chrome

## Escopo e convenções

Este documento rastreia o comportamento observável da automação Ruby para a primeira entrega da extensão. As fontes de verdade são o código ativo, os testes permitidos e as decisões aprovadas em `docs/chrome-extension-ui-decision.md`. `apps/chrome-extension/propose.md` é requisito de produto, não evidência de comportamento legado.

Não foram consultados CSVs, configurações locais, logs, screenshots, PDFs, TXT nem dados pessoais. As referências de linha abaixo são lógicas e correspondem ao estado auditado em 2026-08-22.

Classificações usadas:

- `PARIDADE`: reprodução do comportamento Ruby ativo;
- `ADAPTAÇÃO_MV3`: mudança necessária para sessões, contextos e UI de uma extensão Manifest V3;
- `MELHORIA`: comportamento deliberadamente adicional, equivalente a `MELHORIA_DELIBERADA` no plano;
- `FORA`: não integra a primeira entrega, equivalente a `FORA_DO_ESCOPO` no plano.

Status usados:

- `IMPLEMENTADO`: há destino TypeScript e teste local correspondente;
- `PENDENTE_DOM_REAL`: o código Ruby sustenta o contrato/seletor, mas a compatibilidade com os sites autenticados ainda exige validação manual controlada;
- `FORA`: não será implementado nesta entrega.

## Baseline Ruby permitido

O comando permitido pelo plano, que exclui os testes dependentes de CSV, foi tentado a partir de `apps/standalone/`:

```text
bundle exec ruby -Itest test/all_test.rb --name '/test_week_|test_missing_required_configuration|test_expert_maps_all_hours/'
```

Resultado: **bloqueado antes da carga da suíte**, exit code `127`. O executável resolvido foi `/usr/local/bin/bundle`, cujo shebang aponta para `/usr/bin/ruby3.1`, inexistente neste ambiente; o `ruby` disponível informa `3.2.3`. Portanto, nenhum teste Ruby foi executado e este documento não alega baseline aprovado nem quantidade de testes. Os testes CSV continuaram fora do baseline por segurança.

Na validação da Onda 3 após o ciclo de correção, as execuções separadas terminaram com exit code `0`: 48 testes unitários, 16 testes de paridade, 22 testes de integração e 2 testes e2e passaram (88 no total). O baseline Bundler permanece bloqueado, mas `tests/fixtures/ruby-domain-oracle.rb` carrega os arquivos reais `Ahgora.rb` e `Expert.rb` com Ruby 3.2.3, marcando apenas as gems exclusivas de navegador/prompt como já carregadas e sem abrir Selenium. `tests/parity/ruby-source-oracle.test.ts` usa esse harness sanitizado como golden master cruzado para aritmética permissiva, formato negativo, primeira ocorrência de override, comparação textual/`last wins` e Expert. Os demais casos de `test:parity` continuam caracterizações revisadas contra as expressões Ruby indicadas; não se alega que o baseline Minitest completo passou nem compatibilidade com DOM autenticado.

## Pendências honestas de validação manual

- iframe, rótulos e navegação reais do Ahgora;
- estrutura real do extrato Channel, ordem das linhas e atualização assíncrona;
- opções por prefixo, campos, eventos necessários e reconhecimento de valor pelo Channel;
- estados reais de login, navegação/reconcessão de `activeTab` e múltiplas abas;
- idempotência, fila manual e preenchimento parcial contra o DOM real;
- retomada após encerramento real do service worker (o e2e prova reidratação do painel, mas Chromium/Playwright não expôs encerramento programático do worker);
- nenhuma submissão foi ou será implementada nesta entrega.

Até essas verificações ocorrerem com participação/autorização do usuário, fixtures sintéticas provam apenas o contrato local; não provam compatibilidade com o DOM autenticado.
